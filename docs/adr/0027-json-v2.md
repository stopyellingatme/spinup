# ADR 0027: encoding/json/v2 for request decoding, and Go 1.27 as the minimum

- Status: accepted
- Date: 2026-11-05

## Context

Go 1.27 enables the `jsonv2` experiment by default. The packages `encoding/json/v2` and `encoding/json/jsontext` import with no flag. In Go 1.27, `encoding/json` (v1) runs on the v2 implementation with v1 options.

The source files of the v2 packages carry `//go:build goexperiment.jsonv2`. Go 1.26 cannot build code that imports them. Go 1.27 with `GOEXPERIMENT=nojsonv2` cannot build it either.

A survey of the code (run 20261105-215107, unit J1) measured these numbers on an M1 Max under load:

| Path | v1 | v2 strict |
|---|---|---|
| `DecodeJSON` on a resource body | 2,532 ns, 1,578 B, 12 allocs | 862 ns, 112 B, 3 allocs |
| Decode of a 50-row list | 77,615 ns, 25 allocs | 37,180 ns, 10 allocs |
| The generated list response (oapi-codegen visitor) | 26,126 ns, 5 allocs | 26,058 ns (atomic `Marshal`), 34,103 ns (buffered `MarshalWrite`) |

The v1 decoder has these weak points at a trust boundary:
- It matches field names without case (`{"ROLE":...}` fills the field `role`).
- It accepts duplicate names, and the last value wins.
- It replaces invalid UTF-8 and accepts the value.

Generated resource handlers decode bodies with the oapi-codegen strict decoder (v1 `Decode`). They do not call `httpx.DecodeJSON`. `httpx.RequireJSONFields` skips all parsing when a route has no required field.

## Decision

1. **Go 1.27 is the minimum.** The root module, `kit/`, `plugin-sdk/`, `go.work`, and the generated `api/go.mod` and `api/tools.mod` declare `go 1.27.0`. `stackversions.yaml` sets `go.min` to `1.27`. CI tests Go 1.27 only. `GOEXPERIMENT=nojsonv2` is unsupported. The upgrade Deps phase raises the `go` line of an existing app (ADR 0006 §4), so this change needs no codemod.

2. **`httpx.DecodeJSON` uses v2 with strict options.** It decodes with `encoding/json/v2` and `json.RejectUnknownMembers(true)`. The v2 defaults apply: exact field names, duplicate names rejected, and invalid UTF-8 rejected. Each of these gives a 400 with the generic detail. An empty body and a body with two values keep their specific details. A body over the limit gives 413. Parser text stays private.

3. **The kit checks the body of every generated write route.** A new kit function `httpx.CheckJSONBody(r *http.Request, rules httpx.BodyRules) error` validates the whole document with `encoding/json/jsontext`. `BodyRules` has the fields `Required []string` and `Known []string`. The check rejects these bodies:
   - duplicate names at any depth, and invalid UTF-8 (400)
   - a top-level name that is not in `Known`, when `Known` is set (400, the same detail as an unknown field in `DecodeJSON`)
   - a root value that is not an object (422)
   - a required name that is missing or null (422, with the field errors sorted by name)
   - a body over the limit (413)

   The body stays readable for the next decoder. `RequireJSONFields(r, required)` stays as a wrapper with `Known` unset. It now validates the syntax also when no field is required. The generated `RequireFields` middleware registers rules for every POST, PUT, and PATCH pattern of a resource, with `Known` set to the property names of the request schema. So the oapi-codegen v1 decoder never sees a case variant, a duplicate name, or invalid UTF-8.

4. **Response encoding stays on the v1 API.** It already runs on the v2 engine in Go 1.27. Atomic encoding keeps the promise of `WriteJSON` that a failure leaves the response untouched. Buffered `MarshalWrite` was slower in the generated visitor. List handlers keep their explicit empty slices.

5. **Persisted and protocol JSON do not change in this ADR.** These stay on v1: the lock file (`internal/manifest`), audit events (`kit/audit`), the plugin JSON-RPC protocol (`plugin-sdk`), the secrets parser, the deploy journal, and CLI JSON output. Each one has a wire contract that the v2 defaults change. Examples are `omitempty` on `audit.Actor.ID`, and `omitempty` on the `RawMessage` result of the plugin response. A later change moves one of them only with its own measurement and wire-format tests.

## Consequences

- A client that sends a case variant, a duplicate name, or invalid UTF-8 now gets a 400. Before, the request succeeded. The changelog and `docs/policy/support.md` state this.
- Apps and plugins need Go 1.27 to build. Go 1.26 remains supported upstream until Go 1.28 ships, but spinup drops it now (pre-1.0, no compatibility gates).
- One JSON implementation exists in the kit. There is no build-tag fallback.
