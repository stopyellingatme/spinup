# ADR 0030: API keys and plan quotas

Status: accepted (owner, 2026-11-06)
Date: 2026-11-06
Extends: ADR 0013 section 1 (modules), ADR 0016 (auth rate limit), ADR 0024 (roles), ADR 0025 (audit trail), ADR 0027 (strict request decoding), ADR 0028 (kit migration space), ADR 0029 (the module pattern)

## Context

A generated app authenticates a request only with the session cookie.
A program cannot call the API without a browser sign-in.
The only Bearer check in the kit is the shared deploy token of `kit/deployx`.

The dogfood app jostar (a SEC EDGAR Form 4 tracker) sells a keyed REST API with a web app.
Customers need their own keys, and the app needs quotas for each customer.

The owner decided these points on 2026-11-06. They are binding:

1. The feature is an opt-in module `apikeys` in spinup, in the pattern of ADR 0029. It requires `auth`.
2. Quotas come from named plans in `[apikeys.plans.<name>]` of `spinup.toml`. A plan has a limit for each minute and a limit for each day.
3. A plan belongs to a user. All keys of a user share the budget of the plan.
4. A key has a scope: `read` (GET and HEAD only) or `write` (all methods). A key acts as its user, with the role of the user.
5. Postgres holds a usage counter for each key and each UTC day. The keys page shows the counters. The counters enforce the limit for each day.
6. The operator command `apikeys` and an admin page `/admin/apikeys` change the plan of a user.

## Decisions

### 1. Promise and limits

1.1. A key is a Bearer token: `Authorization: Bearer <token>`. A key request has no cookie session, and no CSRF check applies to it.
1.2. The limit for each minute is in memory, in each process. With N API replicas, a user gets up to N times that limit. This is the same limit as ADR 0016 §7.
1.3. The limit for each day is shared through Postgres. A replica flushes its counts at an interval (default 5s). A user can go past the daily limit by the traffic of one interval on each replica.
1.4. The quota counts only key requests. Cookie requests from the web app are not counted.
1.5. A revoke acts on the next request on all replicas. The lookup reads the database on each key request, with no cache.

### 4. Tokens and storage

4.1. A token is `<prefix>_<secret>`. The secret is 32 bytes from `crypto/rand`, in `base64.RawURLEncoding` (43 characters).
4.2. The table stores `sha256(token)` in `token_hash`. The lookup is by the digest, as for the reset token (`kit/auth/reset.go`). The token is shown once, in the answer to the create request.
4.3. The table stores `display`: the prefix, the underscore, and the first 6 characters of the secret. Lists show `display` to identify a key.
4.4. `AuthenticateBearer` rejects a token without the configured prefix, or with a secret that is not 43 characters, with no query.

### 6. The Bearer hook in `kit/auth`

This is the only change to the stable kit API. `kit/api/current.txt` gets the additions. It is not a break.

```go
// Bearer authenticates the token of an Authorization: Bearer header.
type Bearer interface {
	AuthenticateBearer(ctx context.Context, token string) (context.Context, User, error)
}
// ErrBearerInvalid means the token is unknown, revoked, or expired.
var ErrBearerInvalid = errors.New("auth: invalid bearer token")
func WithBearer(b Bearer) Option
```

6.1. In `(*Auth).Middleware`, after the CSP header, the installed marker, and `a.allow`: if `WithBearer` was given and the request has an `Authorization` header with the scheme `Bearer` (case-insensitive), the request takes the Bearer branch. Without `WithBearer`, the header is ignored, as today.
6.2. The Bearer branch skips `a.csrf.Handler` and `a.sessions.LoadAndSave`.
- A path that starts with `/api/auth/` answers 403 with the detail `An API key cannot call the sign-in routes.` These handlers need a session.
- An empty token, or `ErrBearerInvalid`, answers 401 with `WWW-Authenticate: Bearer error="invalid_token"`, `Cache-Control: no-store`, and the detail `The API key is not valid.`
- Another error answers 500 through `a.internalError`.
- On success, auth sets `user.Role = a.effectiveRole(user.Role)`, puts the user in the context returned by `AuthenticateBearer`, calls the `WithActorContext` function, and calls next through `guardWriter`.
6.3. When a request has a cookie and a Bearer header, the Bearer branch wins and the session is not loaded.
6.4. `GET /api/session` answers the key user (it reads only `UserFrom`). Clients use it as "who am I".
6.5. The code is in a new file `kit/auth/bearer.go`, plus the branch in `auth.go` and one field in `options` and `Auth`.

7.1. `AuthenticateBearer` runs one query. It joins `api_keys`, `users`, and `api_key_plans` on the digest, with `revoked_at IS NULL` and no past `expires_at`. It returns the context with `Request`, and the user with id, email, and the stored role. An unknown, revoked, or expired key returns `auth.ErrBearerInvalid`.
7.2. Input rules: a name is 1 to 64 characters with no line break. A scope is `read` or `write`. An expiry is 0, or 1 to 365 days in whole days. `Create` counts the keys of the user that are not revoked, in the same transaction, and returns `ErrTooManyKeys` at `MaxKeys`.
7.3. All writes to `api_keys` and `api_key_plans` go through `audit.InTx`, as in `kit/x/flags/store.go`.
7.4. `Start` starts the flush loop. It does not fail on a database error. It logs, and `Ready` reports the last flush error. `Close` stops the loop and flushes once more.

### 8. Quotas and the middleware

8.1. `(*Store).Middleware()` acts only when `KeyFrom` returns a request. Cookie requests pass through unchanged.
8.2. In order, for a key request:
1. A path that starts with `/api/me/keys` or `/api/admin/` answers 403 with `An API key cannot manage keys or call admin routes.`
2. A `read` key with a method other than GET or HEAD answers 403 with `This API key is read-only. Try: create a key with the write scope.`
3. The limit for each minute: GCRA keyed by the user ID, burst `PerMinute`, one token every `time.Minute / PerMinute`. It is in memory, with a cap of 100000 users and a sweep of old entries each minute. Model it on `kit/auth/ratelimit.go`. Do not export or change that file.
4. The limit for each day: `used = base + local`. `base` is the database total of the user for the current UTC day, read on the first key request of the user on that day. `local` is the count of this process that the database does not hold yet. When `used >= PerDay`, the answer is 429.
5. On success, `local` and the pending count of the key grow by one.
6. The audit actor gets `Reason: "api_key:<key id>"` when an actor is in the context (`audit.ActorFrom`, `audit.WithActor`).
8.3. Each key answer has `RateLimit-Limit: <per_day>`, `RateLimit-Remaining: <per_day - used>` (at least 0), and `RateLimit-Reset: <seconds to the next UTC midnight>`.
8.4. A 429 answer has `Retry-After` (the GCRA wait for the minute limit, rounded up, at least 1; the seconds to midnight for the day limit), `Cache-Control: no-store`, and a problem whose detail names the plan: `The free plan allows 60 requests a minute. Try again in 3 seconds.` or `The free plan allows 1000 requests a day. Try again after midnight UTC.`
8.5. A database error in step 4 answers 503.
8.6. The flush loop takes the pending counts, upserts them into `api_key_usage` (`count = count + excluded.count`), sets `last_used_at = now()` for each key, and reads the totals of the users again. The users' `local` drops by the counts that the flush wrote.
8.7. OTel: the counter `apikeys.requests` with the attributes `plan` and `outcome` (`ok`, `forbidden`, `minute_limit`, `day_limit`).
8.8. The middleware goes after `authn.Middleware()`, and after the flags middleware when flags is on.

### 9. HTTP routes

All routes are in `kit/x/apikeys/routes.go`. They are not in the OpenAPI spec, for the reason of ADR 0029 §8.1. Bodies go through the decoder of `kit/x/flags/routes.go` (media type, 16 KiB, `httpx.CheckJSONBody`, `httpx.DecodeJSON`). Every answer has `Cache-Control: no-store`.

User routes, guarded by `a.RequireUser`. The middleware rejects them for key requests (8.2), so only a cookie session reaches them:
- `GET /api/me/keys` answers `{"plan":{"name","per_minute","per_day"},"max_keys","today","keys":[Key],"usage":[UsageDay]}`. `usage` covers 30 days.
- `POST /api/me/keys` with `{"name","scope","expires_in_days"}` answers 201 `{"key":Key,"token":"..."}`. Bad input answers 422 with field errors. `ErrTooManyKeys` answers 422 with the detail `You have the maximum of N keys. Try: revoke a key first.`
- `DELETE /api/me/keys/{id}` answers 204, or 404 for a key of another user.

Admin routes, guarded by `a.RequireRole(a.Roles().Admin)`:
- `GET /api/admin/apikeys` answers `{"default_plan","plans":[{"name","per_minute","per_day"}],"accounts":[Account]}`.
- `PUT /api/admin/apikeys/users/{email}/plan` with `{"plan"}` answers 200 with the account. Unknown user: 404. Unknown plan: 422.
- `DELETE /api/admin/apikeys/keys/{id}` answers 204, or 404.

### 17. Out of scope

- Billing. A billing hook calls `SetPlan` later.
- Per-route scopes or an allowlist of routes.
- A shared store for the limit for each minute (ADR 0016 §7).
- Keys for an organization. Keys belong to a user.
- Key rotation with a grace period. Create a new key, then revoke the old one.

## Consequences

- A generated app can sell a keyed API with plans and see the use of each key.
- `kit/auth` gets a small public hook. Other authenticators (for example service tokens) can use it later.
- Key requests pay one indexed query for each request. The quota adds no query, except the first request of a user on a day and the flush.

## Amendment (2026-11-07): a prefix change keeps existing keys

Section 4.4 is replaced. `AuthenticateBearer` rejects a token that is not `<prefix>_<secret>`, with no query. The prefix must match `^[a-z][a-z0-9]{1,15}$`. The secret must have 43 `base64.RawURLEncoding` characters. The configured `prefix` is used only to mint new keys. The lookup uses `sha256(token)` of the whole token, so the prefix is part of the key identity. A key keeps working after a prefix change. A token with a valid secret and a different prefix has a different digest and is rejected. No migration is needed.
